How the code works, and what it does and doesn't prove

A code looks like SER5-0912345-9-1KZ4QW7: chapter prefix, student ID, score out of ten, then a check value.

The check value is an FNV-1a hash of the chapter string plus the student ID, XORed with the score times a constant, printed in base 36. Because the score is folded into the hash, changing the score in a submitted code breaks the check. That is the whole security property.

What it proves:

  • The score wasn't edited after the module produced it.
  • The code was produced for that specific student ID.

What it does not prove:

  • That the student did their own work. Anyone who reads the page source can generate a code, and the problems are all client-side. Treat this as a convenience for honest students, not as proctoring.
  • That the student answered the problems themselves rather than having someone else sit at the keyboard.

Because the problem set is seeded from the student ID, two students comparing answers get different numbers — which is the more useful deterrent in practice.
